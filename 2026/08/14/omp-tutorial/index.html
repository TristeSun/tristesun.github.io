omp（Oh My Pi）使用教程

本教程基于 omp.sh/docs 官方文档整理，重点覆盖 CLI 使用 与 CLI 中 Jupyter Notebook 的使用。omp 是一个可编程的 AI 编码代理（coding agent），由 can1357 开发，官方名称为 Oh My Pi，CLI 命令为 omp。

🚀 快速入门（3 分钟上手）

omp 是什么？ 一句话：一个住在终端里的 AI 编程助手。你在项目目录里把它叫出来，用大白话跟它说你要干什么，它就帮你读代码、改代码、跑命令。 第 1 步：安装（选一条）

bash 
curl -fsSL https://omp.sh/install | bash   # 官方脚本（最简单）
bun install -g @oh-my-pi/pi-coding-agent   # 或 bun 全局装
mise use -g omp@latest                     # 或 mise 管理

装完验证：omp --version。 第 2 步：登录账号

bash 
omp          # 首次运行会自动进入引导向导
omp setup    # 想手动重跑引导也可以

跟着提示登录一个提供商即可（有 Anthropic / ChatGPT / Copilot / Gemini 账号都能用）。 第 3 步：用起来

bash 
cd 你的项目目录
omp            # 打开交互式会话，直接打字聊天
omp -c         # 继续上次没聊完的会话
omp -p 给 README.md 写个简介   # 问一句就退出（适合脚本）
omp @bug.log 看看这个报错是怎么回事  # 带上文件一起问

第 4 步：记住 3 个救命命令

  • /plan 你的需求 —— 先让它做计划，确认后再动手（改代码前强烈建议）
  • /model —— 切换模型（用哪个 AI 大脑）
  • omp --help —— 忘了就查，全部参数都有 遇到问题？ 让它自己诊断：直接问它"报错了，帮我看看"，它自带调试能力。

想知道更多用法？往下翻目录，或点链接直接跳官方文档。

二、CLI 使用详解（重点）

1. 基本语法

bash 
omp [options] [@files...] [messages...]
omp <command> [args] [flags]
  • 裸运行 omp：在当前目录打开交互式会话。
  • 加 -p：打印一个回答后退出（一次性调用）。
  • 带子命令：直接调用该工具，不启动 agent。
  • 任何带值的 flag 都支持 --flag=value 写法。
  • 任何以 @ 开头的参数都当作文件处理，即使夹在 flag 中间。

2. 优先级规则

CLI flag 大于环境变量，大于 ~/.omp/agent/config.yml，大于内置默认值 --api-key 只对本次运行生效、永不持久化，优先级高于一切。

## 三、CLI 中 Jupyter Notebook 的使用（重点）
> 核心结论：**omp 的 notebook 支持是文件转换/编辑，不是 notebook 执行**。`.ipynb` 文件通过 `read` 以"单元格标记文本"的形式暴露给模型编辑；真正的代码执行走 `eval` 工具（Python/JS 持久内核）。两者是分开的两条路径。
### 1. 读取 .ipynb：单元格标记文本
```bash
# 在交互会话里让模型读一个 notebook
read "analysis.ipynb"

# 从 shell 直接读
omp read analysis.ipynb

read 把 .ipynb 当作 notebook（除非加 :raw 选择器），默认视图是带标记的可编辑文本：

text 
# %% [code] cell:0
import pandas as pd

# %% [markdown] cell:1
这是分析说明

# %% [raw] cell:2
...

标记格式：# %% [code|markdown|raw] cell:N。行选择器（如 :50-200）和多段范围选择器都作用在这个虚拟文本上。

2. 编辑 notebook：走 edit 管线

  • 模型用 edit 工具修改上面的虚拟文本，serializeEditedNotebookText 会把虚拟文本往返写回 notebook JSON。
  • 引用已存在但未被使用的 cell:N 时保留原单元格元数据；新单元格创建空元数据；execution_count 与 outputs 保留。
  • 注意：独立的 write 工具不认 notebook——它会用给定字节直接覆盖文件。要用 write 必须给合法的 notebook JSON，而不是标记文本。

3. 执行 Python：eval 工具（持久内核）

需要跑代码时，每个单元格一次 eval 调用，language: "py"：

text 
# 模型内部工具调用（示意）
eval(language="py", code="df = pd.read_csv('data.csv')")
eval(language="py", code="df.describe()")

关键特性：

  • session 模式（默认）：内核按 (session id, cwd, interpreter) 缓存，跨调用保持状态——前一个单元格的变量后一个还能用，这就是 notebook 的"持续内核"体验。
  • per-call 模式：每次调用新建子进程，finally 里必定关闭。
  • reset：reset: true 在本次执行前重置选中的 Python 会话（不影响其他语言运行时）。
  • 内核崩溃自愈：执行前检测到子进程已死会自动替换；执行中死掉会替换内核并重试一次；并发的 reset 会合并。
  • 流式输出：stdout/stderr 实时分块；display/result 渲染 MIME 包（优先级 text/markdown 大于 text/plain 大于 text/html）；JSON 输出树、PNG/JPEG 图像都能结构化捕获。
  • 超时/取消：发 SIGINT，超时后输出带超时标注，下次调用重建内核。
  • 输出截断：超出阈值时完整输出溢出到 artifact 文件，内存里保留 UTF-8 安全的尾部缓冲，返回截断提示与可选的 artifact://<id> 指针。

4. 推荐的 notebook 工作流

text 
1. read 读取 .ipynb 的默认可编辑视图
2. 用 edit 管线修改该虚拟文本
3. 把某个目标 cell 的源码复制进 eval(language="py") 调用执行
4. 逐个执行后续 cell；session 模式下 Python 状态跨调用保持
5. 后续源码改动继续走 edit 管线（整文件 write 必须给 notebook JSON）

当前实现没有一个工具能同时修改 .ipynb 并以内核上下文执行 notebook cell——编辑走 edit 管线，执行走 eval 工具。

变量作用
